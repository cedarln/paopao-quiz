# 🫧 泡泡题库 (Paopao Quiz)

> 一款面向教师资格证考试的移动端刷题应用，支持自定义题库导入、错题本、模拟考试、主题切换与个性化背景。纯前端实现，基于 Capacitor 打包为 Android APK。

## 📦 Releases

### v1.8.0（开发中）

- 🧷 **内置题库改为单一来源生成**：`tools/merge-banks.js` 原先把题库字段手拼成 JS 字符串，只认识 `id/category/question/options/answer/subjective/answerText/explanation/audioUrl`，其余（`optionResults`、`dimensions`、`results` 的分析字段、`audio` 文本）会被静默丢掉，所以测评题库根本不能走它内置。现在按 JSON 原样序列化 `window.QUIZ_DATA[key] = {…}`，字段一个不丢，并在写完后用独立 vm 上下文把生成的文件跑一遍、逐题比对源数据，不通过就非零退出
- 🚧 **加了三道护栏**（都是这次踩过的坑）：镜像文件名按 key 反查已有文件，不再另写一个「同 key 不同文件名」的副本造成用户侧题库分裂；题量比现有镜像变少时拒绝写入（曾经有个注册指向 13 题旧稿 `paper_zzhx.json`，跑一次就把线上 35 题的套卷降级）；源文件缺失或 JSON 解析失败从「警告跳过」改成硬失败（`tmp-build/ms_daofa.json` 是坏 JSON，一路被跳过，坏掉的内置文件因此在仓库里留了好几版）。支持 `--dry-run` 看影响面、`--only <key>` 单个重生成、`--force` 显式确认缩量
- 🧬 **四个内置题库与线上镜像内容对齐**：`zhsz-zhongxue` / `jyzn-zhongxue` / `xk-zhengzhi` / `ms-daofa-zhengzhi` 的源文件早已丢失，注册表改为直接以已上线、已通过校验的 `quizzes/*.json` 为准（`fromQuiz`）。重新生成的内置文件在 App 内实测：200 / 200 / 40（含 10 主观）/ 60 题，首页四张卡齐全
- 🛠 `tools/build-www.js` 新增内置↔镜像一致性门禁：逐个解析 `js/data/*.js`，与 `quizzes/` 同 key 镜像逐题比对，内容不一致或干脆没有镜像（用户删除内置后无法找回）都非零退出。这两份过去各改各的，症状只是首页少一张卡，不报错、控制台以外看不出来
- 🎧 **听力音频不再打进 APK**：66 个 m4a（约 2.98 MB）从打包白名单里移出，`www/` 从 3.58 MB 降到 636 KB。题库里的 `audioUrl` 写仓库相对路径 `audio/<题库key>/<id>.m4a`，App 拼 `raw.githubusercontent.com/cedarln/paopao-quiz/main/…` 在线取；地址解析优先级为「绝对 `audioUrl` → `audio/` 仓库相对 → 题库 `audioBase` 拼接 → `audioBase` + 题号（可用 `audioIds`/`audioRange` 限定、`audioExt` 指定扩展名）」，没有 `audioBase` 的裸相对路径视为无效（包里没这个文件，只会 404）
- 🌀 **在线题库选择界面重排**：题库名普遍很长（「思想政治学科知识与教学能力 模拟卷 第1回」），旧布局是单行 + 跑马灯，手机上一次只能看到个头。现在名字独占整行（最多两行后省略），体积与 `key` 放第二行，状态改用左边框着色 + 徽章；顶部新增搜索框（可按名称或 key 过滤，如 `vocab`、`paper`、`综合素质`）与「全部 / 可获取 / 已加载」状态筛选（计数随搜索联动），「刷新列表」挪到标题栏，列表改为撑满弹窗高度。375px 宽的手机上同屏可见题库从 3 个左右增加到 6 个，26 个题库全部名字完整可见、无横向溢出
- 💾 **下载下来的音频进 IndexedDB 缓存**（对象库 `audio`，键 `<题库key>::<文件名>`，值是 Blob）：进考试/套卷时并发 3 路预取本卷未缓存的听力，命中缓存重播不再发网络请求，离线也能听；预算 80 MB，超出按最久未听（`lastUsed`）逐出。传送门弹窗顶部新增「已缓存听力 N 段 · X MB」与一键清空，回收站「彻底删除」/「清空回收站」会连带删掉该题库的音频缓存。不做听力的用户从此不用为音频付出包体，题库越加越多也不会把 APK 撑大
- 🩹 修两个顺带暴露的旧问题：从传送门重新导入「曾被彻底删除」的内置题库时，`hiddenKeys` 标记没清，看着导入成功、重启 App 又消失；切题时上一题的听力继续播放、按钮还亮着「播放中」，会让人误以为当前题在播
- 🚨 `tools/build-www.js` 再加一道音频引用门禁：扫 `quizzes/*.json` 与 `js/data/*.js` 里所有 `audio/…` 路径，文件不在仓库就直接非零退出。音频漏 `git add`、或只推 JSON 没推音频，用户端症状只是「音频加载失败」，构建期拦下来比事后查划算

#### 签名与发版

密钥库 `keystore/paopao-quiz.jks` 与密码 `android/keystore.properties` 均在 `.gitignore` 内，不入库。v1.7.2 起使用新签发的密钥（`CN=Paopao Quiz`，SHA-256 `a1593dbf…051a`）。

发版顺序（`cap sync` **不会**清理旧 assets，必须先删再同步，否则套娃副本会一路带进 APK）：

```bash
ELECTRON_RUN_AS_NODE=1 "/Applications/Qoder CN.app/Contents/MacOS/Qoder CN" \
  tools/build-www.js                          # 白名单生成 www/，核对版本号 + 脚本语法自检
rm -rf android/app/src/main/assets/public     # 清掉上一次同步的残留
ELECTRON_RUN_AS_NODE=1 "/Applications/Qoder CN.app/Contents/MacOS/Qoder CN" \
  node_modules/@capacitor/cli/bin/capacitor sync android
cd android
JAVA_HOME=/Users/linan/Library/Java/JavaVirtualMachines/temurin-17.jdk/Contents/Home \
  PATH="$JAVA_HOME/bin:$PATH" ./gradlew assembleRelease
```

这台机器没有独立的 `node` / `npx`，`package.json` 里的 `npm run www` / `npm run sync` 跑不起来，请用上面的 Electron 形式（`build-www.js` 结尾也会打印同样一条）。

## ✨ 功能特性

### 📚 核心刷题
- **7 个内置教资科目**：综合素质（小学/中学）、教育知识与能力（中学）、教育教学知识与能力（小学）、保教知识与能力（幼儿园）、学科知识与教学能力（语文/数学）
- **顺序 / 随机两种模式**，可选题量（5 / 10 / 15 / 20 / 全部）
- **即时答案反馈**：选中后立即显示对错与解析
- **答题回顾**：结束后可查看全部题目、对错情况与解析

### 📥 题库导入
- 支持导入 **JSON 格式** 自定义题库（英语、日语、公考等任意科目）
- 同主题题库导入冲突时可选 **覆盖** 或 **追加**
- 导入的题库持久化存储，可单独删除

### 🌀 传送门（在线题库广场）
- 题库 JSON 统一放在本仓库的 **`quizzes/` 目录**，App 内通过 GitHub Contents API 在线列出
- 点击即可在线加载 / 更新题库（走同一套校验与冲突处理），无需手动下载导入
- 每个文件显示「未加载 / 有更新 / 已加载」状态（按文件内容 sha 判断，发布即更新），待获取的排在前面，并用卡片左边框着色标示状态
- 顶部有搜索框（按展示名 / 文件名 / 题库 key 过滤，如 `vocab`、`paper`、`综合素质`）和「全部 / 可获取 / 已加载」筛选，chip 上的数字随搜索联动
- 弹窗顶部还显示「🎧 已缓存听力」的段数与体积，可一键清空（v1.8.0 起听力音频按需下载并缓存到本地）
- **发布新题库**：把符合 [配置格式](#-题库配置文件格式) 的 JSON 上传到 `quizzes/` 目录即可（GitHub 网页端 Add file → Upload files 就行）。文件名可用 `展示名~文件名.json` 让 App 里显示更友好的名字，例如 `英语高频词~english-500.json`
- 用户在 App 传送门里点右上角「🔄 刷新」即可拿到最新题库
- **临时下线某个题库**（不让用户检测到，但保留在仓库里随时可恢复）：把它的 JSON 从 `quizzes/` 移到 `quizzes-draft/`。因为「列表只列 `quizzes/` 目录」这条规则写在**已安装到用户手机里的 App** 里，改代码只影响升级后的版本，移走文件才是对所有旧版本立刻生效的唯一办法

  ```bash
  node tools/stage-bank.js hide  mbti-16personalities   # 下线
  node tools/stage-bank.js show  mbti-16personalities   # 开放
  node tools/stage-bank.js status                       # 两边各有什么
  ```

  已经导入过该题库的用户，本地数据不会被远程删除，只是无法再新增加载。

## 📝 题库配置文件格式

题库文件为 JSON 格式，UTF-8 编码。完整规范见 [`samples/CONFIG_FORMAT.md`](samples/CONFIG_FORMAT.md)。

### 基本结构

```json
{
  "version": "1.0",
  "key": "english-vocab-basic",
  "name": "英语基础词汇",
  "icon": "🇬🇧",
  "description": "英语常用词汇练习",
  "questions": [
    {
      "id": 1,
      "category": "词汇-动词",
      "question": "选择单词 abandon 的正确中文释义：",
      "options": ["放弃，抛弃", "接受，承认", "适应，调整", "钦佩，赞美"],
      "answer": 0,
      "explanation": "abandon vt. 放弃，抛弃。"
    }
  ]
}
```

### 字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `key` | string | ✅ | 题库唯一标识（英文小写+连字符） |
| `name` | string | ✅ | 题库名称 |
| `questions` | array | ✅ | 题目数组 |
| `icon` | string | ❌ | emoji 图标，默认 📝 |
| `description` | string | ❌ | 题库描述 |
| `category` | string | ❌ | 分类标签 |
| `exam` | object | ❌ | 套卷预设：`count` 题量、`minutes` 总时长、`preserveOrder` 保持卷面顺序、`sections` 分节（`name` / `count` / `minutes`）与 `description`。带 `preserveOrder` 或 `sections` 的题库会自动启用**套卷模式**，一键整卷开考，按节独立计时 |
| `audioBase` | string | ❌ | 按题号推断音频文件名时的地址前缀（必须 `http(s)://` 开头），适合音频托管在自己的 CDN。仓库内题库不用写，`audioUrl` 用相对路径即可 |
| `audioIds` / `audioRange` | array | ❌ | 配合 `audioBase`：`audioIds` 列出哪些题号有音频，`audioRange` 写 `[起始题号, 结束题号]` 闭区间 |
| `audioExt` | string | ❌ | 配合 `audioBase` 的扩展名，如 `.mp3`，默认 `.m4a` |

### 题目字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `question` | string | ✅ | 题干 |
| `options` | array | ✅ | 选项数组（≥2） |
| `answer` | number | ✅ | 正确答案索引（从 0 开始） |
| `explanation` | string | ❌ | 答案解析 |
| `category` | string | ❌ | 题目分类（用于分类筛选） |
| `audio` | string | ❌ | 听力朗读文本（系统 TTS 兜底；Android WebView 不支持 Web Speech API，真机上放不出声，所以听力题务必给 `audioUrl`） |
| `audioUrl` | string | ❌ | 音频地址，优先于 TTS。写仓库相对路径 `audio/<题库key>/<id>.m4a` 即可，App 会拼成 GitHub raw 在线地址下载；也支持 `https://` 绝对地址 |

> 听力题示例：`"audio": "女：あした 何を しますか。男：…（完整对话与问题）"`，播放按钮会自动出现在题干下方。
>
> 💡 从 v1.8.0 起听力音频**不再随 APK 打包**：音频放在仓库 `audio/<题库key>/<id>.m4a`，进考试时按需在线下载（并发预取）并缓存到本地，之后离线可重播；题库被彻底删除时缓存一并清掉。所以发布带听力的题库只要把 m4a 和 JSON 一起推到 GitHub，**不需要重新发版**，也不做听力的用户不会为音频付出安装包体积。

> 💡 你可以把 doc / pdf / url 链接发给我，我会帮你制作成对应的题库配置文件。

## 💾 本地存储说明

应用使用 `localStorage` 持久化以下数据：

| Key | 说明 |
|-----|------|
| `quiz-imported-banks` | 用户导入的题库数据 |
| `quiz-recycle-bin` | 回收站中的题库 |
| `quiz-hidden-keys` | 已彻底删除的内置题库 key |
| `quiz-wrong-book` | 错题本 |
| `quiz-stats` | 学习统计（答题数、正确率、打卡） |
| `quiz-theme` | 当前主题 |
| `quiz-bg` | 自定义背景（图片/视频 base64） |

听力音频从 v1.8.0 起存在 **IndexedDB**（库 `quiz-storage`，对象库 `audio`，键 `<题库key>::<文件名>`，值是 Blob），不占 localStorage 配额；上限 80 MB，按最久未听逐出，传送门弹窗里可一键清空。
